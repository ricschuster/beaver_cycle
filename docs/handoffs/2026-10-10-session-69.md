# Session Handoff: 2026-10-10

## Summary

Session 69 added the save. The game saves by itself and offers Continue or New game at the start. The choices were made with the
author first: `localStorage`, one slot, autosave every 30 seconds, ask at the start, a version number, the coach inside the save.

## Completed

- `src/persist/save.ts`: the envelope `{ version, savedAt, world, coach }`, encode and decode, `migrate` (version 1 only), the
  load and write helpers, `wantsSave`, and `ago`. Ponds' typed arrays go in as base64. Fields added to `WorldState` later take
  the new game's value, so they need no version bump. An unreadable or newer save is copied to `beaver-cycle.save.unreadable`.
- `src/ui/continueCard.ts`: the "Welcome back" card; New game asks twice. `src/ui/coach.ts` got `resume` and `state`.
- `src/main.ts`: loads after the stage setup (so a continued game replaces the ready-made lodge), saves every 30 s, on a stage,
  season or generation change, on `visibilitychange` hidden and `pagehide`, and once at the start. `lastGeneration` starts at the
  loaded generation so a continued game does not toast "A kit is born".
- No save, no read, in an automated browser unless `?save=1`, and never with `?day`, `?time`, `?age`, `?stage`, `?lodge`, `?fly`
  or `?save=0`, so a test link cannot overwrite a real game.
- Design note `docs/design/26_saving.md`; the manual's two "cannot save yet" lines now say it saves.
- Checks: typecheck, 540 unit tests (9 new in `src/persist/save.test.ts`), build, markdownlint on `docs/`, and
  `save.spec.ts` (2 new) with `smoke.spec.ts` all passed locally.

## Risks or decisions needed

- A save written by an older build is read by a newer one with defaults for missing fields. A change that needs more than a
  default (a rename, a unit) must bump `SAVE_VERSION` and add its step to `migrate`, or old saves load wrongly.
- The save is about 50 to 100 KB per pond-heavy game as text; `localStorage` allows about 5 MB. Many ponds are fine, but watch it.
- A game started with New game is replaced at once, so a mis-tap on the second press cannot be undone. There is no backup of it.
