## Completed

- PR #327: `game` is now a small gate job that needs `unit` (typecheck, unit tests), `build` and `e2e`, which run in parallel.
  A `changes` job lists the PR's files through the API and skips those three when only `docs/` or `*.md` changed. `game` fails
  on any failed or cancelled job, so it stays the single required check and branch protection did not need to change.
- PR #328: the browser tests (76 tests in 18 files, most of the run time) run as three Playwright shards. The Playwright
  browser is cached. `.github/workflows/warm-cache.yml` saves that cache and the npm cache from `main`, because a PR can read
  caches from `main` but not from another PR, and CI only runs on PRs. It runs when `package-lock.json` changes, on Mondays and
  Thursdays, and by hand (`gh workflow run warm-cache.yml`).
- Ran the warm workflow once by hand after the merge. `gh cache list` shows both caches under `refs/heads/main`.
- Timing: a full code run went from about 3m to 2m15 (that run had a cold cache). Not yet measured with a warm cache.

## Risks or decisions needed

- A docs-only PR is defined as every changed file under `docs/` or ending in `.md`. A change to `public/manual.html`, a
  workflow or `package.json` counts as code and runs everything. If the files API fails, `changes` fails and so does `game`,
  so it errs on the safe side.
- The `changes` job lists at most 3000 files of a PR. A PR bigger than that would be read as partly listed. Not a concern here.
- The caches are dropped after 7 days unused. The twice-weekly schedule keeps them alive. If scheduled workflows are
  disabled after 60 days without repo activity, the cache goes cold and PRs get slower, but not wrong.
- Decision for the author, carried from session 70: turn on `enforce_admins` so the checks also bind admin merges?
- Older risks, still true: a save change that needs more than a default must bump `SAVE_VERSION` and add its step to
  `migrate`. Android WebView may clear `localStorage`. A New game replaces the save with no backup.
