# Session Handoff: 2026-10-18 (session 151)

## Summary

The memory work (#604, memory use and leaks) is measured, one leak fixed, and the issue closed. A soak test tours the six locations and reads the
heap, the three.js object counts and the ground bytes. On an SM-X210 the whole app is about 250 MB and flat over 36 game years.

## Completed

- PR #634: `tests/e2e/memory.spec.ts`, dev only `__game.memory()`, `TileStore.bytesByLevel()`, `Renderer.memory()`, and
  `docs/design/38_memory.md` (numbers and a provisional budget).
- PR #635: `__game.skipYears(n)` and a second soak test that moves the clock on a game year at each jump. The leak it confirms:
  other families' kit ids carry the year, so their beaver models (and the parents') piled up in the scene for good. They are
  now recycled (`recycle` in `src/render/renderer.ts`). Without it 48 years took the scene from 2365 to 8239 geometries and the
  heap from 40 to 83 MB; with it 1537 to 1687 and 36 to 39 MB.
- PR #636: the tablet numbers in the note. A debug build under the app id `com.beavercycle.game.mem` went beside the installed
  game (never touched), was driven over CDP (`adb forward` to `webview_devtools_remote_<pid>`, Playwright `connectOverCDP`) with
  `dumpsys meminfo` after each lap, and was uninstalled again. Total PSS 212 MB at start, 249 MB flat from lap 3; GPU side about 110 MB.
- #604 closed with the numbers.
