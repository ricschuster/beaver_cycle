# Session Handoff: 2026-10-18 (session 152)

## Summary

The stress test by script (#603) has a first version: `npm run stress` plays laps of the game on a desktop browser or a tablet and writes
a JSON report, with budgets and a baseline from both. Both ran clean. The one finding is a stall of up to 930 ms when a dream starts
(#638).

## Completed

- PR #639: `tools/stress/stress.mjs` and `docs/design/39_stress_test.md`. A lap is six location jumps, a walk at x5 at each, winter
  and a game year, a sleep, and a dream; every second lap ends with a reload that continues the save and a freeze and wake of the
  page. It records frame times, the heap after a collection, GPU counts and ground bytes, and fails on errors, a crash, a lost
  context, a clock that goes back, or a budget.
- Baseline in the note. Desktop 17 min: walking p95 16.8 ms, heap 34 to 37 MB flat. SM-X210 31.6 min, 11 laps, 5 reloads: p50
  11.1 ms at 90 Hz, worst p95 33.4 ms, 12.9 frames over 50 ms a minute, heap 33 to 36 MB flat, the clock kept at every reload.
- #638 filed: a dream's start stalls one frame for 370 to 930 ms on the tablet (500 to 650 ms on the desktop). Jumps cost up to about
  300 ms, not filed.
- Things the runs taught, now in the runner and the note: the picker needs Start after New game; an automated browser does not save
  without `save=1`; the picker's text is English, so the desktop context is `en-US`; the heap slope is read at the same point of each
  stretch between reloads (short stretches gave a false 1.2 to 1.6 MB a minute).
